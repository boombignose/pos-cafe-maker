# ติดตั้งระบบร้านบน Windows — รุ่น 0.2.0

ชุด **shop** ใช้ PostgreSQL จริงและหลายหน้าจอใน LAN ชุด **demo** และ GitHub Pages เก็บข้อมูลจำลองเฉพาะ browser เป็นคนละโหมด ไม่มี Docker/API key/payment gateway

ต้องการติดตั้ง Docker เพิ่ม: อ่าน [คู่มือ Docker Desktop/WSL 2 บน Windows](DOCKER-WINDOWS.md) เป็นทางเลือกสำหรับเตรียมเครื่อง รุ่นนี้ยังไม่มี Dockerfile/Compose สำหรับ POS และ `Start.cmd` ไม่ใช้ Docker

## ติดตั้งครั้งแรก

1. ใช้เครื่อง Windows 64-bit หนึ่งเครื่องเป็นเครื่องกลาง ติดตั้ง [Node.js 24 LTS](https://nodejs.org/en/download) และ [PostgreSQL 17 หรือ 18 จากหน้าผู้ผลิต](https://www.postgresql.org/download/windows/) รวม command-line tools เครื่องลูกใช้ browser ไม่ต้องติดตั้งฐานข้อมูล ไม่จำเป็นต้องใช้รหัส PostgreSQL ของ installation เดิมกับ POS
2. ดาวน์โหลด `pos-cafe-maker-shop-v0.2.0.zip` จาก Release แตก ZIP ให้ครบในโฟลเดอร์ที่เขียนได้ ห้ามเปิดไฟล์จากใน ZIP ดับเบิลคลิก **Start.cmd** ครั้งแรกต้องมีอินเทอร์เน็ตเพื่อ `npm ci --omit=dev` หลังจากนั้นระบบร้านใช้ LAN ได้โดยไม่ใช้บริการ cloud
3. ระบบสร้างฐานข้อมูลส่วนตัวที่ `%LOCALAPPDATA%\pos-cafe-maker` ไม่ใช้/ล้างฐานข้อมูล PostgreSQL เดิม เปิด browser ไปที่ `http://localhost:3001/#pos` หน้าต่าง Start ต้องเปิดค้างไว้
4. เปิด `SETUP-TOKEN.txt` ในโฟลเดอร์ข้อมูลร้าน คัดลอกรหัสตั้งร้านใส่ในเว็บ ตั้งชื่อร้าน ที่อยู่ กระดาษ 58/80mm และบัญชีเจ้าของร้าน รหัสผ่านเฉพาะร้านอย่างน้อย 12 ตัวอักษร อย่าแบ่งปัน token หรือ config ให้คนอื่น Setup ปิดเมื่อสร้างเจ้าของร้านแล้ว ไม่มี password ร่วมกัน
5. จัดการร้าน → วัตถุดิบ → เพิ่มชื่อ/หน่วย/ขั้นต่ำ แล้วรับเข้าเป็นปริมาณจริงพร้อมเหตุผล เพิ่มเมนู ราคา สูตรและตัวเลือก สร้างบัญชีแคชเชียร์/บาร์ใน **ทีมร้าน** อย่าใช้ปุ่มเพิ่มข้อมูลร้านตัวอย่างกับยอดสต็อกร้านจริง
6. เข้า **หน้าขาย** เปิดกะ ระบุเงินสดเริ่มต้น แล้วทดลองด้วยสินค้าทดสอบและคืนเงิน/ปรับสต็อกให้ถูกต้องก่อนเริ่มร้านจริง การโอนต้องให้พนักงานตรวจยอดเงินเข้าบัญชีจริงเอง ช่องยืนยันไม่ได้เชื่อมธนาคาร

หากเริ่มไม่ได้ ให้ดูข้อความใน Start และ `postgres.log` ในโฟลเดอร์ข้อมูลร้าน ต้องมี `pg_ctl`, `initdb`, `pg_dump`, `pg_restore` หาก PostgreSQL อยู่ที่อื่น ให้ตั้ง `POS_PG_BIN` เป็นโฟลเดอร์ bin ก่อนเรียก Start โปรแกรมจะไม่ลบ data folder ที่มีอยู่หรือซ่อมโดยล้างฐานข้อมูล

## เปิดหลายหน้าจอ

เครื่องกลางและจอลูกต้องอยู่ LAN เดียวกัน ใช้ URL `LAN:` ที่ Start แสดง เช่น `http://192.168.1.20:3001/#pos` หรือ `/#bar` ตั้ง IP เครื่องกลางให้คงที่/จอง DHCP ให้เจ้าของเครือข่ายเปิด firewall เฉพาะ TCP3001 บนเครือข่าย **Private** ของร้านและจำกัดเครื่องที่เข้าถึง ไม่เปิด PostgreSQL55432 ไป LAN ไม่ forward port ออกอินเทอร์เน็ต

รุ่นเริ่มต้นใช้ HTTP จึง **ไม่เข้ารหัสรหัสผ่านและ session ระหว่างเครื่องลูกกับเครื่องกลาง** ใช้เฉพาะ LAN ที่เชื่อถือได้ หากมี guest Wi-Fi/เครือข่ายร่วมให้แยกเครือข่ายและให้ผู้ดูแลติดตั้ง HTTPS ก่อนใช้ ตัวอย่าง Caddy reverse proxy ภายใน:

```text
pos.local {
    tls internal
    reverse_proxy 127.0.0.1:3001
}
```

ผู้ดูแลต้องตั้งชื่อ `pos.local` ให้ resolve ไปเครื่องกลาง และติดตั้ง CA ของ Caddy ที่เครื่องลูกตาม [เอกสาร Caddy](https://caddyserver.com/docs/automatic-https#local-https) ไม่ข้ามคำเตือนใบรับรอง ตั้ง environment `PUBLIC_ORIGIN=https://pos.local` และ `COOKIE_SECURE=true` ก่อนเปิด launcher แล้วเข้าเว็บผ่าน HTTPS อันเดียวกันทุกครั้ง

## เปิด–ปิดและอัปเดต

- เริ่มวัน: Start.cmd → เข้าระบบ → เปิดกะ ปิดวัน: นับเงิน ปิดกะ แล้ว Ctrl+C ที่หน้าต่าง Start ข้อมูลเก็บนอกโฟลเดอร์โปรแกรม เปิด Start ใหม่หลังรีบูต ไม่ได้ติดตั้ง Windows service หรือ Startup อัตโนมัติ
- ถ้าไฟดับ/ปิดหน้าต่างกะทันหัน อย่าลบ data folder เปิด Start ใหม่ PostgreSQL จะกู้ transaction ที่ commit แล้ว กะเดิมยังอยู่ ตรวจยอดกะก่อนขายต่อ
- อัปเดต: สำรองก่อน → ปิด POS → แตก shop ZIP รุ่นใหม่ไปโฟลเดอร์ใหม่ → Start จากโฟลเดอร์ใหม่ โปรแกรมใช้ data directory เดิมและรัน migration ที่ยังไม่เคยใช้ เก็บโปรแกรมเก่าไว้ อย่ารันสองรุ่นพร้อมกัน และอย่าย้อนรุ่นโดยไม่ตรวจความเข้ากันได้ของ schema
- macOS/Linux: ติดตั้ง Node และ PostgreSQL 17/18 แล้วเรียก `sh start.sh` ข้อมูลอยู่ `~/Library/Application Support/pos-cafe-maker` บน Mac หรือ `~/.local/share/pos-cafe-maker` บน Linux ใช้ `POS_DATA_DIR` เปลี่ยนตำแหน่งข้อมูลได้ก่อนติดตั้งครั้งแรก ไม่คัดลอก cluster ขณะเปิดอยู่

## สำรองและกู้คืน

ระบบตรวจทุก 5 นาทีขณะที่เปิดและสำรองวันละครั้งตามวัน Bangkok เมื่อมีบัญชีร้านแล้ว ดูสถานะ/สั่งสำรองได้ที่ **ตั้งค่าร้าน** หรือ **Backup.cmd** (macOS/Linux: `npm run backup`) ไม่มีการลบ backup เก่าอัตโนมัติ ต้องตรวจพื้นที่ว่างและคัดลอกสำเนาออกจากเครื่องร้าน

ไฟล์คู่ `backups/pos-....dump` และ `.dump.json` มีเวลา/schema และ SHA256 เก็บทั้งคู่ ข้อมูลสำรองมีประวัติร้านและ password hashes ให้เก็บในพื้นที่ที่เข้าถึงได้เฉพาะเจ้าของ ห้ามแจกไปกับ repo การสำรองไว้ในดิสก์เดียวอย่างเดียวไม่ป้องกันดิสก์เสีย

กู้คืนเฉพาะ backup ที่ระบบนี้สร้างและคุณเชื่อถือ ใช้ PostgreSQL major เดียวกับตอนสำรอง (17→17 หรือ18→18):

1. ปิดทุกจอขายและหยุด Start ด้วย Ctrl+C ก่อน เก็บโปรแกรม/config และ backup ปัจจุบันไว้
2. Windows: ลากไฟล์ `.dump` ไปวางบน **Restore.cmd** ไฟล์ `.dump.json` ต้องอยู่ข้างกัน หรือใช้ `node scripts/shop/cli.mjs restore "C:\path\pos-....dump"`
3. ระบบตรวจ checksum กู้เข้า **ฐานข้อมูลใหม่ที่ว่าง** ใน transaction ตรวจ schema แล้วสลับ config เฉพาะเมื่อสำเร็จ ไม่ drop/เขียนทับฐานข้อมูลเดิม หากล้มเหลวก่อนสลับ config เดิมยังอยู่ เมื่อสลับสำเร็จแต่เขียน status metadata ไม่ได้ จะรายงานสำเร็จพร้อมคำเตือน ให้ตรวจสิทธิ์/พื้นที่ว่างและสำรองใหม่ ฐานข้อมูลที่กู้ไม่ผ่านอาจเหลือไว้เพื่อวิเคราะห์ อย่าลบโดยเดาเอง
4. เปิด Start ใหม่ ทุกบัญชีต้อง login ใหม่ ตรวจยอดบิล/กะ/สต็อกกับวันที่ backup และใบเสร็จจริง รายการหลังเวลา backup ไม่อยู่ในฐานข้อมูลที่กู้คืน ต้องให้เจ้าของกระทบยอดกับฐานข้อมูลเดิม/หลักฐานเงินจริงก่อนขายต่อ
5. หาก browser มีรายการชำระค้างจากก่อนกู้ ระบบจะห้ามส่งซ้ำ เข้าบัญชีเจ้าของที่ **browser เครื่องนั้น** → ตั้งค่าร้าน → ตรวจบิลค้าง → ระบุผลตรวจและยืนยัน โปรแกรมบันทึกผู้ยืนยัน/เหตุผลแล้วปลดเฉพาะตะกร้าค้าง ไม่ลบ/คืนเงินบิลที่ขายแล้ว จากนั้นกลับเข้าบัญชีแคชเชียร์

## เมื่อเครือข่ายหลุดระหว่างขาย

ตะกร้าเก็บใน browser แยกตามบัญชี เมื่อส่งชำระจะเก็บรายการและ key เดิมก่อนส่ง ถ้าไม่ทราบผล ปุ่มเปลี่ยนจำนวน/รับเงินจะล็อก ใช้ **ตรวจผลรายการเดิม** เท่านั้น รวมถึงหลัง reload หรือ login ใหม่ อย่ารับเงินซ้ำ อย่าล้างข้อมูลเว็บไซต์ เปลี่ยน browser/profile/URL หรือรีเซ็ตตะกร้าก่อนตรวจบิลสำเร็จ

การตั้งราคาหรือสูตรใหม่มีผลกับบิลใหม่ บิลเดิมเก็บราคา สูตร และข้อมูลร้าน ณ เวลาขายไว้ ประวัติบิลเลือกวันและพิมพ์ซ้ำได้ ใบเสร็จไม่ใช่ใบกำกับภาษี เครื่องพิมพ์ใช้ OS driver และ browser print ให้เลือกขนาดจริงและปิด header/footer ของ browser ยังต้องลองกับเครื่องพิมพ์ของร้าน

## สำหรับผู้พัฒนาจาก Source ZIP

```sh
npm ci
npm run build:shop
npm run shop
```

`npm run dev`/`npm run build` ปกติยังเป็นเดโม ห้ามเสิร์ฟ dist เดโมแทนระบบร้าน อ่าน [BACKEND.md](BACKEND.md) หากต้องใช้ฐานข้อมูลภายนอกแทน managed cluster และ [TEST-REPORT.md](TEST-REPORT.md) ก่อนอ้างผลตรวจบนระบบของตัวเอง
